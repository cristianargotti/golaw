# 4. a TOML decoder for the gitleaks and squawk files and the Codex configuration

## Context

`policy.gitleaks-generic` reads `.gitleaks.toml`, whose rules and allowlists carry regular expressions, often as multi-line literal strings, and `policy.squawk-config` reads `.squawk.toml`. The standard library has no TOML decoder. A reader of a declared subset would make a valid configuration a stated limit, and a stated limit fails the pipeline, which the owner's zero friction goal forbids for a file the tool itself accepts.

Codex records in its user `config.toml` which hook definitions the person trusted (`[hooks.state]`), whether its hooks feature is on and which projects are trusted. Installing the Codex hooks and diagnosing them need that record to tell an installed hook from a trusted and an active one; a reader of a subset would report a hook the person approved as untrusted on a configuration Codex itself accepts.

## Decision

Use `github.com/BurntSushi/toml`, which has no dependency, at an exact pinned version, with three readers: `internal/checks/policyfiles`, decoding each file whole through the snapshot; `internal/install` (`CodexTrusted`), which reads the hook trust of the Codex `config.toml` to print the `/hooks` step after an install; and `internal/doctor`, which reads the same file for the hook trust, the hooks feature and the project trust. Both readers of the Codex configuration only read it: the `/hooks` review of Codex is the one writer of its trust records.

## Consequences

One module enters the binary. The version enters seven days after publication. A syntax error names the file and the line the decoder reports, and leaves the check unmeasured, never clean. A Codex configuration the decoder refuses is reported with the file named, and neither the installer nor doctor ever writes it.
