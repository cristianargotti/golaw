# 3. x/mod to read go.mod

## Context

The dependency checks of the policy family match the direct requires of `go.mod` exactly against the front matter of the decision records, follow a `replace` that points inside the repository and report one that points outside as unmeasured with the directive named (A14). A `go.mod` may hold several require blocks, single-line requires, comments that mark a requirement indirect, retractions and toolchain lines; a text match of that grammar would answer a false clean or a false finding.

## Decision

Use `golang.org/x/mod/modfile`, the parser the go command itself builds on, at an exact pinned version, inside `internal/checks/policyfiles` only. The family reads `go.mod` through the snapshot and hands the bytes to `modfile.Parse`; no command runs.

## Consequences

One module enters the binary and brings `golang.org/x/tools` into the module graph, which no package of the kit imports and which deps-age judges like every module. The version enters seven days after publication.
