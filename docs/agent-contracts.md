# Agent integration contracts

M1 targets Claude Code. The validated host version is 2.1.299. The minimum supported version is 2.1.295 because installed handlers require onFailure: block.

## Installation and exec form

The plugin owns hooks/hooks.json and its verbatim skill copy. Hooks do not live in settings.json. The installer adds narrow permissions.deny Read rules for private key and keystore files, the Terraform variable files Terraform loads by itself (terraform.tfvars and *.auto.tfvars, and their JSON form), the service account files whose name ends in service-account.json or service_account.json, SSH keys, and cloud credential files.

Each handler uses exec form:

```json
{
  "type": "command",
  "command": "golaw",
  "args": [
    "hook",
    "claude"
  ],
  "timeout": 10,
  "onFailure": "block"
}
```

No shell parses that invocation. doctor checks that executable resolution identifies the running binary. Windows acceptance proves that the bare name resolves to golaw.exe through PATH. The fallback of the installer copying the binary under ${CLAUDE_PLUGIN_DATA} is not built in M1: it waits for the Windows live record and ships only if the bare name fails there.

## Events

| Event | Matcher | Contract |
| --- | --- | --- |
| PreToolUse | Write, Edit, NotebookEdit | Write supplies file_path and content. Edit supplies old_string, new_string, replace_all, and edits when present. Reconstruct the candidate in memory. Deny NotebookEdit with a compatibility reason until decoded. |
| PreToolUse | Read | Judge tool_input.file_path against secret-material rules, both by the name it asks for and by the file its links lead to. |
| PreToolUse | Bash, PowerShell | Judge command text, cwd, and tool name without executing the command. |
| PostToolUse | Write, Edit, NotebookEdit | Measure resulting content when prospective measurement was unavailable. |
| PostToolUse | Bash, PowerShell | Detect changed content from the tool_use_id snapshot. A file bashEditDiff names gets the answer that detection gives it, so one a move brought from commits the command did not create, one whose status alone changed and one git cannot convert are answered as they are without it; the files bashEditDiff names are judged as they stand only when no baseline classifies what the command changed. |
| PostToolUseFailure | Bash, PowerShell | Detect changes even when the command failed after writing. |

Accept one JSON object of at most 8 MiB, the read bound of a file, so a write the snapshot could hold is judged whole, and validate the envelope for the named adapter. An envelope from another agent is denied. A positively unenrolled location receives a valid allow. Missing or weakened policy in an enrolled repository is denied. An input over the bound is read to its end in bounded memory for its header, the content of a write read past and never held, so each field counts wherever the host writes it, and it is checked as an event within the bound is: its JSON to the last byte and its envelope and tool input as their decoders check them, so an input they refuse within the bound is cannot judge over it, and NotebookEdit is denied for compatibility at any size. In an enrolled repository a post event is judged from that header as any post event, its detection reading git and the baseline of its pre event and never the event, a write is judged by the name rules over the path it names, so a name the tree forbids is denied and any other is allowed with a notice naming what was not measured, a write of golaw.yml stays denied, and any other event is cannot judge. The hook holds a string of such an input up to 64 KiB under a field that names the event or a file and up to 4 KiB under any other, and reads a longer one past; a field it reads that holds one, and an input whose other bytes pass 8 MiB, is cannot judge.

The location of a write or read is the deepest existing directory above tool_input.file_path, or notebook_path for NotebookEdit, after the name is expanded the way the host expands it, trimmed, a leading ~ or ~/ taken from the home the hook process shares with the host, on Windows a /c/ name read as that drive, and cleaned, and every symbolic link in it is followed, the last one included, dangling or not. Claude Code 2.1.299 already sends the hook the path it expanded; the hook expands it again, so a host that sends the name as the model wrote it is placed the same way. A name that starts from the home is cannot judge when the hook process has no home, and the Unicode normal form the host also applies is not mirrored. When no enrolled repository holds that file, the directory that holds the entry the name opens is tried next, then every directory that holds a link the name passes through, so a link, of the file or of a directory above it, carries a write or a read neither into nor out of an enrolled repository unjudged; a write it carries out of one is refused as cannot judge. The repository that holds the target governs it whatever cwd the session reports. A read outside every enrolled repository falls back to the repository of cwd. A shell event is located at cwd.

Change detection after a shell command asks git status, with the ignore rules of the universe and without taking the index lock, for the paths that differ from HEAD in the index, from the index in the worktree, or that git would add, before the command and after it, and identifies only those: a path git status reports clean at both ends is unchanged and never read, unless the command moved HEAD: then git diff-tree names, once, the paths that differ between the HEAD of the pre event and the HEAD after the command, the HEAD of an unborn branch read as the empty tree, and each is compared with the blob the earlier HEAD held there; of the paths it finds changed that git status reports clean after the command, only those the commits the command created changed are judged: the commits git log names, once, between the two HEADs, every commit of HEAD after an unborn branch, that were committed in the second the pre event started or later, git recording whole seconds, and carry the name and email git var GIT_COMMITTER_IDENT answers in the repository. Of a merge among them, the files it holds apart both from every parent, as git log --cc names them in the same question, and from the merge git makes of its parents by itself, as git log --remerge-diff names them, once for every such merge, are judged: its resolution of a conflict and the files it added or edited, while a file it took from one side whole and one git merged by itself are named in the notice; a git older than 2.36, which has no --remerge-diff, or a remerge git fails leaves each file such a merge holds apart from every parent to a notice naming it. So a file a command writes and commits is judged, the first commit of its branch included, as is a file an amend, a cherry-pick, a rebase that replays a commit or a merge --squash followed by a commit brings and the resolution a merge commit of the command holds, while every file a pull, a checkout, a merge or a reset brings from commits the command did not create is named in a notice, twenty by name and the rest counted, that asks for no fix and leaves it to the pipeline; a path git status names after the command is judged as any other, bytes a developer left dirty that the command commits unchanged report nothing, and an orphan checkout, which leaves every file with the bytes the commit it left held, reports nothing. Git log and git var run only when the move brought such a path, and git log --remerge-diff only when a merge the command made holds one apart from every parent, so a command that leaves HEAD in place asks git nothing more, unless it starts a merge it leaves in progress. A path git status reports unmerged after the command that it did not name before holds the conflict git wrote from both sides: it is named in a notice and judged by the event that writes its resolution, whatever left the conflict, a merge, a pull, a rebase, a cherry-pick or a stash. When the command started the merge, its bytes are first compared with that conflict, the merge git makes by itself with the strategy options of the command, git merge-tree --write-tree and one git cat-file --batch asked once for every such path, line for line with a carriage return before a line end and the names after a conflict marker of seven or more characters ignored: bytes the commit MERGE_HEAD names holds whole are named in the notice, bytes HEAD holds whole are unchanged and report nothing, the conflict waits, and any other bytes, a resolution the command wrote without git add, are judged in the same event; a resolution the command writes for a conflict a rebase, a cherry-pick, a revert or a stash left, which no MERGE_HEAD names, waits for a later event, a stated limit. A command that starts a merge it leaves in progress, MERGE_HEAD present after it and not before, read as a file, has git merge-tree --write-tree make, once, the merge of HEAD and the commit MERGE_HEAD names as git makes it by itself, a conflict it cannot resolve in its markers, and git cat-file name, once, the blob that merge and that commit hold at each file staged with its bytes on disk, both with a temporary object directory in front of the objects of the repository, removed after, so the repository receives no object; a file whose staged blob is one of those two is named in a notice that asks for no fix, a file git merged from both sides and a conflict resolved with the side of that commit taken whole included, while a file whose staged blob is neither, the command's resolution of a conflict or its own edit, a file only the local side added or changed since the fork included, is judged, as is a file the command wrote after the merge or left unstaged, and a merge already in progress before the command leaves the files the command writes judged as any other. A file a commit the command created before it started that merge changed, as when it commits its own change and then merges, is judged whatever the merge staged there, as is such a file the command left unmerged with the bytes HEAD holds, the commits of the command asked of git log and git var once for the event, as after any move; when git cannot tell them, each such file is a notice naming it. A merge git cannot make by itself to compare, an octopus merge, one under a git older than 2.38, which has no merge-tree --write-tree, or one git fails, leaves each file the merge staged to a notice naming it. A merge made with the strategy option -X ours or -X theirs, left in progress or committed, is also compared with the merge git makes with that option, which the pre event reads from a git merge or git pull the text of the command runs plainly, in each spelling git takes, -X ours, -Xours, --strategy-option ours and --strategy-option=ours, and which git merge-tree --write-tree makes once more, only for the files the merge without it leaves apart, with one git cat-file for a merge in progress and one git diff-tree for every such merge commit: a file whose bytes that merge holds is named in the notice. Another strategy option, an -X of another program or after the git command ends, and an option an alias, a script or the configuration gives, is not read, so a file such an option resolved hunk by hunk is judged as the command's resolution, a stated limit. A move git cannot compare, such as one from a commit the command pruned, is a notice naming the changes of the command and each path whose status alone changed, and commits git cannot list, or a committer it cannot name, leave each path the move brought to such a notice, while a path whose bytes changed since the pre event named it is still judged. A commit the command makes under another identity, or dates before the pre event, through GIT_COMMITTER_DATE or a rebase that keeps the dates of the commits it replays, reads as a commit it did not create, a stated limit. Git status trusts what the index records: a file the index marks assume-unchanged, by git update-index or core.ignorestat, or skip-worktree reads clean whatever its bytes, and so does a file rewritten to its size with its modification time put back, as cp -p, tar or touch -r leave it, while its stat data still matches the index, which core.checkStat minimal with core.trustctime false always lets it; a command that rewrites such a file is invisible to detection at both ends, without a notice, and left to the pipeline. A path git status names at one end only is compared by its bytes: one named before the command only is identified as it is after it, and one named after it only is unchanged while its bytes are still the blob the HEAD of the pre event held there, so a mode change, a commit of bytes already dirty and a soft reset that leaves a committed file staged report nothing, while a file written back to its committed content is judged; bytes that are not that blob as they lie on disk are named as git would store them, through the end of line rules and the filters of the path, asked of git hash-object once for every such path and writing no object, so a file git converts on its way in is left alone when only its status changed, and one git cannot convert, as when a required filter fails, is a notice naming it and never a change, while a path git status found edited under its own mode, whose bytes git already compared through those conversions, is judged changed without that question unless its bytes hold a carriage return, so an edit only a filter undoes is judged. It identifies a symbolic link by its class and the length of its link text and a submodule by its class alone, because the snapshot holds the bytes of neither, the model contract carries neither a link text nor a submodule revision, and no check follows a link or enters a submodule: a link already changed against the index and retargeted again to a text of the same length and a submodule moved to another revision are excluded from detection. Neither carries a content rule, so the exclusion hides no finding.

## Exit and output contract

| Situation | Exit | Output |
| --- | --- | --- |
| Allowed pre event | 0 | Valid allow result |
| Judged pre denial | 0 | hookSpecificOutput.permissionDecision is deny; permissionDecisionReason is English; systemMessage uses the configured human language |
| Cannot judge | 2 | Nonempty English stderr reason |
| Post detection | 0 | decision is block with a reason; execution has already happened |
| Post failure detection | 0 | additionalContext describes the detected change |
| Allowed with a gap | 0 | hookSpecificOutput.additionalContext of the event names what was not measured and that the pipeline judges it; systemMessage names the same path in the configured language |
| Unexpected process failure | Not emitted intentionally | Host applies onFailure: block |
| Host timeout or missing binary | No binary answer | Installed onFailure: block must stop the tool, established live |

The internal deadline is shorter than the ten second host timeout. Reaching it before a pre event is answered produces a denial; a post event it reaches is allowed with a notice when no finding was established, because its tool already ran. A finding the hook established before the deadline is still fed back, with the deadline notice appended. So is a finding of a check the deadline stopped between two of its files, which the check established whole before the deadline. Post feedback never claims rollback.

Post detection never blocks on what it could not measure: a file over the read bound that the command changed, a change set over 65536 paths or 64 MiB, a pre event that left no baseline, a move of HEAD git cannot compare, a file git cannot convert to compare and the deadline each leave a notice the agent reads, naming the path when there is one, the paths of one cause in one sentence that names twenty and counts the rest, for the agent and in the language of the policy for the person, so a pull git cannot classify, when git var cannot name the committer, is one bounded sentence, and the pipeline judges what they left; a file it could measure is still judged, and a finding still blocks. A file over the read bound is identified by the size, modification time, change time and inode of its lstat, on Windows its size and modification time only: a command that leaves it alone leaves no notice, a rewrite that changes any of them is named, and a rewrite that restores them all is the stat limit of git status stated above. The name rules judge every file, one over the read bound included, so a name the tree forbids is fed back after a command and denied before a write although its bytes are not measured; only a rule that needs the bytes the hook does not hold leaves the file to the notice. A rule that reads a file beside its target, the files of a package goast.secret-fields reads for a redaction and goast.goleak for the goleak import, and the files a command stages for shell.shape, leaves to the notice only the verdict that file could change: a redaction or an import a readable file holds is still found, and a commit whose files alone break its theme is still refused. A Write over a file beyond the read bound is judged on its whole content, and an Edit of such a file, which cannot be reconstructed within the bound, is judged by the name rules and otherwise allowed with the same notice.

## Trust

Interactive settings-file hooks wait for folder trust. Noninteractive sessions can run those hooks without that dialog. Those facts do not establish plugin behavior before workspace trust. doctor reports plugin trust as unknown until live evidence establishes it.

Keeping hooks in the plugin avoids the settings-file hook import used by Cursor. Installation, enablement, integrity, trust, and observed dispatch remain separate facts.

## Offline acceptance

The M1 matrix runs on Linux, macOS, and Windows. It installs twice, checks unchanged receipts and foreign settings, and invokes the exact installed command with closed stdin in an isolated home without credentials.

Required rows deny a dash write, a secret read, and a --no-verify commit; allow their controls; and deny malformed input, a crash, and the forced internal slow path.

The empty output row, in the protocol-limit category, records the fault and proves no denial: the host treats exit 0 with no output as an allow, which is also the valid allow the adapter answers, so a binary that exits cleanly without an answer is a limit of the protocol that no hook closes.

The doctor-json row decodes doctor --json after an installed hook ran: every artifact matches its receipt, the hook names the built binary, every hook blocks on failure, and a source build is reported as metadata, never verified.

Each result identifies category, agent, OS, agent version, binary digest, PASS, FAIL, or SKIP, and whether the milestone requires the row. SKIP never counts as PASS. A failed run closes with the rows that fail it, so a release run stopped by a skipped required row names that row.

claude plugin validate --strict is a required row. claude plugin test is the host's runner for hook modules written against its testing kit; the plugin ships command hooks and no module, so the host refuses the command and the row is recorded as not applicable, never as a pass. Neither proves installation or live dispatch. The kit also validates handler fields because the vendor validator accepted an unknown field during the initial investigation.

Offline acceptance proves the adapter and installed invocation. Only a live record proves dispatch, trust behavior, host failure behavior, and resulting target state.

## Live record: 2026-10-14

Host: Claude Code 2.1.299 on macOS. The daily denials of 2026-10-14 came from the predecessor guard during normal use.

The timeout probe was a standalone project settings hook, separate from that guard. Its PreToolUse Write handler ran sleep 20 with timeout 3 and onFailure: block. It was executed through claude -p in two turns at 0.53 USD. The host refused the write, hello.txt remained absent, and the reported reason was: timed out; blocking because onFailure is "block".

Both records are host evidence for Claude Code 2.1.299 on macOS. Neither identifies a golaw binary or its digest, establishes dispatch of the golaw plugin, or authenticates a release. The timeout probe does not prove the missing-binary case.

Before M1 release, the owner records one dated golaw session on macOS in docs/live/claude-darwin.json: an allowed control, a denied write, a host timeout and a missing binary, each with its outcome and target state. The denied write, the timeout and the missing binary must leave the target unchanged. The timeout case puts a program named golaw that sleeps past the ten second timeout first on PATH; the missing binary case takes golaw off PATH.

That record names the owner, environment, credential boundary, spending limit, schedule, retention, agent version, and the SHA-256 of the binary the session installed: the reproducible darwin/arm64 build of the tagged source, CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -trimpath -buildvcs=false ./cmd/golaw with Go 1.27.0, the go-version of release.yml. A commit that only adds the record leaves that build unchanged; a toolchain bump changes it and needs a new record.

go run ./tools/acceptance reads the record: the host-timeout and host-missing-binary rows pass only when the record is complete and names the candidate digest. An absent record, or one naming another binary, is SKIP. The release lane runs the harness with -release before any draft, and SKIP never counts as PASS there, so no tag publishes without the record.

Linux and Windows have no live M1 enforcement claim. Codex CLI and Cursor are outside M1.
