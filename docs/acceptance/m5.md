# M5 acceptance

Every local check is optional. Remote CI or the platform pipeline is the only hard gate.

Reproduce every row with `go run ./tools/acceptance -m5` from a checkout of the kit. Each row runs under a home of its own below the temporary directory of the run, installs the synthetic fixture bundle from a local bare repository, generates its own release material and runs the candidate the report names; no row runs an agent or reads a real configuration directory. The rows need no network; the preparation fills the module cache from the public module proxy when the cache is cold (the candidate build behind the local proxy, the pinned tools golaw setup installs). The release run, `go run ./tools/acceptance -release`, requires the same rows.

| Field | Value |
| --- | --- |
| Candidate version | 0.5.0 |
| Candidate binary SHA-256 | `430711394521e007ffb44b549ac25d3b594fa8de66fe3bc78e2b7e0159074ede` |
| Execution location | a local machine, macOS 26.4 on arm64 |
| Date | 2026-10-23 |

Linux and Windows rows count only from a native run of the m5 job, never from macOS or a cross build. SKIP never counts as PASS. A cell without a retained native run says not run.

## Remote gate

No remote rejection is recorded: the generic limitation of docs/profiles.md holds, and the kit claims no remote hard gate. A profile's remote gate is whatever the adopting platform runs; the owner records a demonstrated rejection in docs/live/remote-gate.json before the kit claims one.
