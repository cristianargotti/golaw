# M4 acceptance

This page records the M4 acceptance rows and the native evidence retained for them. Local checks remain optional. Remote CI or the platform pipeline is the only hard gate. An offline row proves the installed command and the answers of the candidate binary, never host dispatch, trust or host failure handling; [agent contracts](../agent-contracts.md) states the assurance per agent, event, tool and operating system that this evidence supports.

## Reproduce

Run the M4 catalog from a complete candidate checkout:

```sh
go run ./tools/acceptance -m4
```

The command builds the candidate with go build -trimpath and installs every agent twice in an isolated home: HOME, USERPROFILE, CODEX_HOME, CLAUDE_CONFIG_DIR and the XDG directories point into a temporary directory that holds no credential, so no file of your own agent configuration is read or written. Each Codex and Cursor row runs the installed command as the hooks file names it, through sh -c on macOS and Linux and through both cmd.exe /c and powershell.exe -Command with commandWindows on Windows, and closes stdin at the end of the payload. The m4-vendor row needs the Codex CLI 0.163.0 on PATH and is SKIP without it; the release gate and the m4 job install that pinned CLI. The Claude rows of the assurance matrix come from the M1 catalog, go run ./tools/acceptance, which needs the claude executable on PATH for its vendor rows.

The m4 job of the CI file runs the same command natively on ubuntu-latest, macos-latest and windows-latest with the pinned Codex CLI. Linux and Windows rows count only from a native run of the m4 job, never from macOS or a cross build. SKIP never counts as PASS. A failed row keeps its status and detail, and the report closes with the rows that fail the run. The report is printed at the end, so while the command runs it names each catalog on stderr as it starts and once its rows are measured, and the log of a run the job's bound cancels shows the catalog it stopped in.

## What each category establishes

- The adapter corpora and the red and near fixtures prove the answers of the installed binary to those payloads on the OS that ran them. They prove no host dispatch, no trust and no host timeout behavior.
- The reason rows compare the shared English reason only on the response surfaces that carry one: m4-reason/secret-read compares the human lines of the Claude Read and the Cursor beforeReadFile answers, because beforeReadFile has no agent message, and m4-reason/dash-write reads the Cursor reason from the postToolUse Write feedback, because Cursor writes are captured and allowed, never denied before the write.
- m4-failure/codex-host-timeout records fail open, never fail-closed protection: the harness put a fault that sleeps past the timeout in place of the binary and observed it, and the host answer it names is documented, not a retained host observation. m4-failure/cursor-host-timeout is the same simulated fault with the documented failClosed answer.
- m4-order/second-kit-before and m4-order/second-kit-after hold only for the stub second kit and the install, upgrade and uninstall steps they ran; m4-trust/changed-definition holds for doctor reading a changed Codex handler as revalidation required in the isolated home.
- m4-vendor/codex-execpolicy proves that the pinned vendor validator loads the rules file of a project-scope install and forbids every prefix. A vendor validator does not prove host dispatch.
- No Windows row ran, so neither cmd.exe /c nor powershell.exe -Command executed the launcher in this evidence.

## What M4 done still needs

Codex support needs the contracted live record docs/live/codex-darwin.json and the m4 job green natively on Linux, macOS and Windows. Until both exist, every Codex row stays documented only or proven offline from its own native evidence, and Codex is not yet supported. Cursor remains a compatibility preview even when every offline adapter and launcher row passes. When the native runs and the record exist, their immutable run links and the record are added here and the matrix cells they prove are reconciled again; the missing runs waive no required row.
