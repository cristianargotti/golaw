# Generators

Every check on the developer's machine is optional. The pipeline or remote CI is the only gate.

golaw writes the shape of a port, an adapter, a use case, a handler and their wiring from a contract, with the tests that cover every line of that shape, and leaves the agent the domain logic in holes. The agent decides what a method does; golaw decides how it is laid out, named, wrapped, tested and wired, so the code comes out within the standards on its first run. golaw never calls a Sonar server, a scanner or its API: the kit proves the conditions of the remote gate with its own measures, the golden slices below, and the gate itself stays in the pipeline.

## Contracts

A contract is the small file the agent or the person edits; everything the rules already fix is derived from it. Contracts are owned files of the repository and are never generated.

| Contract | Generator | Output | Runs in the hook |
| --- | --- | --- | --- |
| a port interface in the consuming package, `<area>/ports.go` | golaw | the fake, the contract suite runner, the compile time assertions, the contract test of each adapter, the wiring of the port | yes, in process |
| the use case entry of the manifest: ports consumed, input, output | golaw, through `golaw new usecase` only | `Deps`, `UseCases`, `NewUseCases(deps Deps)`, each use case type, its constructor and its action constant | no, it changes only through the command |
| `api/openapi.yaml` | oapi-codegen v2.8.0, strict server over `std-http-server`, then golaw | request and response types and `StrictServerInterface` under `api/gen`, then the handler struct and its assertion | yes, with its receipted binary |
| `db/queries/*.sql` and `db/migrations/*.sql` | sqlc v1.31.1, then golaw | typed queries under `sqlcgen`, then the repository struct, constructor, action constants and assertion | yes, with its receipted binary |
| a goverter converter interface, `<area>/convert.go` | goverter v1.11.1 | struct to struct converters | never, goverter loads packages |

A port is read with `go/parser` alone: the interface's name, its doc comment, each method's parameters and results as written, and the imports of its file. A port the engine cannot judge without types (a generic interface, an embedded interface of another package, a method set built by an alias) is refused with the construct and its line named, and the person writes that port by hand under the escape of the skill rule below. The engine never guesses a type.

## Kinds

Every kind writes a regenerable part, files whose first line is `// Code generated by golaw <version> kind=<kind>@<n>; DO NOT EDIT.`, and an owned part, written once and the repository's from then on. Phase M7.1 ships template `@1` of every kind. The examples use the area `growth`, the port `Ledger`, the use case `ReadPlan`, the SQL adapter `postgres.Plans`, the HTTP adapter `metagraph.Client` and the handler package `cockpitapi`.

| Kind | Template | Command | Regenerable part | Owned part |
| --- | --- | --- | --- | --- |
| adapter-http | adapter-http@1 | `golaw new adapter http metagraph.Client --port meta.Graph` | `zz_generated_client.go`: the action constants, `ClientConfig`, `Client`, `NewClient(cfg ClientConfig) *Client` with the default bounded client, `var _ meta.Graph = (*Client)(nil)`; `zz_generated_client_contract_test.go` | `client.go` with one hole per method over the shared request helpers; `client_test.go` with one red test per hole over the shared TLS test server and the seed hole of the contract suite; `doc.go` when the package has none |
| adapter-sql | adapter-sql@1 | `golaw new adapter sql postgres.Plans --port growth.Ledger` | `zz_generated_plans.go`: the action constants, `type Plans struct { queries *sqlcgen.Queries }`, `NewPlans(db *sql.DB) *Plans`, `var _ growth.Ledger = (*Plans)(nil)`; `zz_generated_plans_contract_test.go` | `plans.go` with one hole per method; `plans_test.go` with one red test per hole over the scripted driver and the seed hole; `plans_integration_test.go`, the contract suite against a real database under the `integration` tag; `plans_internal_test.go` when the kind writes a mapper; `doc.go` when the package has none |

| port | port@1 | `golaw new port growth.Ledger --usecase ReadPlan` | `growth/ledgertest/zz_generated_fake.go`, the fake over the shared recorder; `zz_generated_suite.go`, the runner; `zz_generated_suite_test.go`, the suite against the fake | the interface stub with a hole for its methods on the line of its type, appended to `growth/ports.go` when the area does not declare the port yet (a new `ports.go` carries the package comment when no file of the area has one); `growth/ledgertest/cases.go` with one hole per method |
| support | support@1 | written by every command | `internal/gensupport/zz_generated_*.go` and its `porttest`, `sqltest` and `tlstest` packages, each file with its test | none |

| wiring | wiring@1 | written by every command | `cmd/<main>/zz_generated_wiring.go`: `Infra`, `Wire(infra Infra) *http.ServeMux` with one constructor call per adapter bound to its port, one `NewUseCases(Deps{...})` per area and one mount per handler, and `Run(ctx, serve) int`, which serves until an interrupt and answers the exit code; `zz_generated_wiring_internal_test.go`, which runs Wire and both outcomes of Run | `cmd/<main>/wiring.go` with `Serve` and the hole `wiring.infra` for the pool, the clients and the configuration; `wiring_internal_test.go`; `main.go`, one call `os.Exit(Run(context.Background(), Serve))`, when the package has none. `golaw new adapter-sql` and `golaw new adapter sql` are the same command, as are the two spellings of the HTTP adapter. The decisions the templates fix:

- One use case per `verb_object.go`, with `New<Verb><Object>` and `Execute(ctx, in)`; the consuming package declares its ports and the composition root chooses the implementation.
- A port is never created alone: `golaw new port` requires `--usecase`, an existing use case or a new one, whose `Deps` consumes the port, because a port nothing consumes is an `iface` finding.
- A constructor takes the port values or one `Deps` or `Config` struct, never more.
- The SQL adapter's struct holds the sqlc `Queries` and nothing else; which sentinel to map and which refusal to answer live in the owned method, stated in its hole.
- The handler is the one kind with two generators in sequence: oapi-codegen writes the server interface under `api/gen`, then golaw writes the handler that implements it.

## Holes

An owned method starts as a hole:

```go
// ReadPlan reads the plan of one account.
func (p *Plans) ReadPlan(ctx context.Context, account growth.AccountID) (growth.Plan, error) {
	// golaw:hole plans.read-plan call p.queries.ReadPlan; map sql.ErrNoRows to growth.ErrPlanNotFound; wrap every other error with wrap(err)
	return growth.Plan{}, gensupport.Hole("plans.read-plan", ctx, account)
}
```

The marker is one line, `// golaw:hole <id> <constraint>`. The id is `<name>.<method in kebab case>`, unique in the repository; the constraint states what to do and every limit the rules put on it, so the agent reads no other file to learn the pattern. The body returns `gensupport.Hole`, which wraps `gensupport.ErrNotImplemented` with the id and takes the method's parameters, so an open hole never panics, never answers nil and raises no unused parameter finding. Each hole has a red test in the owned test file, the first test of its method, which fails with `hole <id> is open: <constraint>` until the method stops answering the sentinel; the agent replaces its single case with the table of domain cases. A hole is closed when its marker is gone and the method no longer calls `gensupport.Hole` with its id; the state is read from the source on every run and never stored.

Until the agent declares a method, a port stub is an empty interface: the lint asset excludes modernize and iface on a `ports.go` line that opens an interface with its `golaw:hole` marker, so make ci right after `golaw new` fails only at the red tests and `golaw gen --check`, and a declared port, which has lost the marker, is judged by both again. The engine never rewrites or deletes owned code. A new method of a port, or a new operation in `api/openapi.yaml`, appends a hole stub at the end of the owned file of each implementation and a red test at the end of its test file. A method gone from the contract is a decision line, and the compiler or `unused` names the orphan. To remove an adapter, a use case or a handler, delete its owned files and run `golaw gen`, which removes the entry and deletes its regenerable files while their bytes still match what the run read. Write the migration and the query before `golaw new adapter sql`, so the kind finds the query each method calls.

## The support package

Shared behavior is called, never copied: a helper copied into every package with one changed prefix is a duplication finding, and a fix made once would have to be made everywhere. Every kind calls one regenerable package, written by the first `golaw new` at the path of `generate.support`, default `internal/gensupport`, standard library only:

- `zz_generated_errors.go`: `ErrNotImplemented`, `ErrPortMissing`, `Prefix(action string) func(error) error`, the error idiom, and `Ready(action string, ports ...any) error`, the nil port guard of every use case.
- `zz_generated_hole.go`: `Hole(id string, args ...any) error`, and `HoleOf[T any](id string, args ...any) (T, error)` for an unexported function that answers a value before its error, so its open hole raises no finding that the value is always zero.
- `zz_generated_recorder.go`: the recorder every fake delegates to, so no two fake methods share a body.
- `zz_generated_httpx.go` and `zz_generated_errors_httpx.go`: the bounded client, `Get`, `Send`, `Status` and `Decode`, each request built with its context and every body read through a limit.
- `sqltest`: a scripted `database/sql/driver`, so the red tests and the domain cases of a SQL adapter need no database.
- `tlstest`: a TLS test server whose handlers check every write, so no test holds an `http://` literal.
- `porttest`: the mechanical cases every implementation of a port passes.

Each file has a regenerable test beside it that covers every line of the package.

## The manifest and the generate block

`.golaw/gen.yml` records each kind instance; it is written only by `golaw new` and `golaw gen`, never by an agent and never by the hook:

```yaml
golaw-gen: 1
support: { path: internal/gensupport, template: support@1 }
entries:
  - kind: adapter-sql
    template: adapter-sql@1
    name: postgres.Plans
    contracts:
      - { path: internal/application/growth/ports.go, symbol: Ledger }
      - { path: db/queries/plans.sql }
    regenerable:
      - internal/adapters/out/postgres/zz_generated_plans.go
      - internal/adapters/out/postgres/zz_generated_plans_contract_test.go
    owned:
      - internal/adapters/out/postgres/plans.go
      - internal/adapters/out/postgres/plans_test.go
```

It holds no hash of generated output and no hole state: drift is computed by rendering again and holes by reading the owned sources, so two branches that each added a kind merge as a plain append. Unknown or duplicate keys fail, and entries stay sorted by kind and name.

The layout lives in the optional `generate` block of `golaw.yml`, outside the floors:

```yaml
generate:
  layout:
    port: internal/application/{area}
    usecase: internal/application/{area}
    adapter_sql: internal/adapters/out/{package}
    adapter_http: internal/adapters/out/{package}
    handler: internal/adapters/in/{package}
    wiring: cmd/{main}
  support: internal/gensupport
  third_party:
    sqlc_out: internal/adapters/out/postgres/sqlcgen
    openapi: api/openapi.yaml
    openapi_out: api/gen
```

`init` detects the layout of an existing repository: under each candidate root it counts the packages that hold hand written Go files and ignores a directory whose Go files all carry a generated header. An empty repository gets the defaults above; two candidates with hand written packages for one kind are an error that names both and the key to set. `sqlc_out` is derived as the `sqlcgen` directory of the SQL adapter path and rendered into the managed `sqlc.yaml`; a moved path in an enrolled repository is an `init --update` diff the person reviews. `ladder.hook_regenerate` is local convenience, never a floor.

## Commands

| Command | What it does | Exit |
| --- | --- | --- |
| `golaw new <kind> <name> [flags] [--dry-run] [--json]` | writes one kind with its holes and red tests, the support package on first use, the wiring and the manifest entry; `--dry-run` prints the diff and writes nothing | 0 written, 1 refused with the reason, 2 usage or a contract that cannot be judged |
| `golaw gen [path] [--json]` | regenerates every regenerable file, appends the stubs of new methods, runs the pinned sqlc, oapi-codegen and goverter through `go tool -modfile=tools/go.mod`, skipping with a `skipped <tool> <config>: not applicable` line each one whose inputs the checkout never wrote and whose output holds no file, as `--check` does, then the mechanical fixes and the safe linter autofixes | 0, 1 when a decision is pending, 2 when a generator failed with its output named |
| `golaw gen --check [path] [--json]` | renders in memory and writes nothing; fails on drift (a regenerable file that differs, a missing one, an entry whose contract is gone, a stale third party output) and on any open hole | 0 clean, 1 drift or an open hole, 2 unmeasured |
| `golaw map [--budget <tokens>] [--area <area>] [--json]` | prints the layers, the ports and their methods, the adapters, use cases, handlers and contracts, then every other file marked handwritten with its reason, open holes first, within 2 000 tokens by default | 0, 2 outside an enrolled repository |

The lines they print:

```text
golaw new adapter-sql postgres.Plans: 4 files written, 3 holes open
written internal/adapters/out/postgres/zz_generated_plans.go
hole open internal/adapters/out/postgres/plans.go:41 plans.read-plan call p.queries.ReadPlan; map sql.ErrNoRows to growth.ErrPlanNotFound; wrap every other error with wrap(err)
golaw gen: 3 files changed, 1 hole opened, 0 closed, 0 decisions
golaw gen --check: drift internal/application/growth/ledgertest/zz_generated_fake.go differs from its rendering: run golaw gen
golaw gen --check: hole open internal/adapters/out/postgres/plans.go:41 plans.read-plan: fill it and its red test
golaw gen --check: clean, 0 drift, 0 open holes
```

`golaw gen --check` runs first in the `generate-check` target of `make ci`, so a hand edit, logic hidden in a generated file and a forgotten hole all fail the remote gate; `init` never arms it locally.

## The agent path

When an agent's post event writes a contract the manifest names (a port file, `api/openapi.yaml`, a query or a migration), through Write, Edit, `apply_patch` or a shell command whose change detection names it, the hook regenerates within the same event:

1. The golaw kinds of the changed contracts, in process: the regenerable files that differ are written and the stubs of new methods appended.
2. sqlc on a query or migration change and oapi-codegen on an OpenAPI change, from their receipted binaries, then step 1 again for the kinds that read their output. goverter never runs in a hook: a converter change answers `run golaw gen: goverter regenerates converters outside the hook`.
3. The mechanical fixes on the Go files the event or step 1 wrote.
4. The feedback.

Each external tool is killed at 1.5 s, and the external work of one event stops at 3 s. A killed tool, a missing one or a managed configuration that no longer matches leaves the third party output as it was and answers `not regenerated in the hook: run golaw gen` with the cause, never a denial and never a finding. The hook writes only the files the manifest lists for the changed contract, the stubs and the formatting, only while the bytes on disk still equal what the event observed, and never `golaw.yml` or `.golaw/gen.yml`; a second hook that finds the generation lock held answers `regeneration deferred: run golaw gen`.

Generated files are read only for agents, with the contract to edit named in the reason. Claude Write, Edit and NotebookEdit, Codex `apply_patch` Update File, Delete File, Move and Add File over a generated file, and a shell redirection, `tee`, `sed -i`, `cp`, `mv` or `rm` whose target is a literal generated path are denied at the pre event; on Cursor the same writes are fed back after the event. A file is generated when its base carries the header before the package clause, or when the manifest lists it as regenerable. sqlc output names its query file and oapi-codegen output names `api/openapi.yaml`. A write of `.golaw/gen.yml` and a bare `golaw:handwritten` marker are denied the same way. A person is never denied: the hooks govern agents, and `golaw gen --check` catches a person's hand edit in CI.

The mechanical fixes need no decision: `go/format.Source`; the certain import fix, removing an import never used and adding one whose name maps to exactly one package of the standard library or the module, an ambiguous name reported with both paths; and the pinned `golangci-lint fmt` from the receipted binary. The autofixes that load packages run only in `golaw gen`. A fixed file is written only when its bytes differ, and the feedback names it.

The feedback lists only what the agent must act on, for the entries of the event's contracts and the files it wrote, at most 20 lines per file and never twice for the same content:

```text
golaw regenerated from internal/application/growth/ports.go (port Ledger): 3 files, 0 drift
hole open internal/adapters/out/postgres/plans.go:88 plans.archive-plan ArchivePlan: call p.queries.ArchivePlan; wrap every other error with wrap(err)
hole closed internal/adapters/out/postgres/plans.go plans.read-plan
decision internal/adapters/out/postgres/plans.go:120 (*Plans).PurgePlans is no longer in port Ledger: delete it or restore the method in internal/application/growth/ports.go
```

The person reads the same lines in the configured language: `arquivo gerado`, `lacuna aberta`, `lacuna fechada`, `decisão` and `deriva`, with the same path, line and id, and the constraint in English as the agent reads it.

`ladder.hook_regenerate: false` turns the regeneration off without a finding, and the mechanical fixes with it; the read only denials stay while the agent guard is installed.

## The skill rule

The skill of every agent opens with this rule:

Run `golaw map` before you explore. Create a port, adapter, use case or handler with `golaw new`; never edit a generated file, edit its contract and the hook regenerates it. Fill the `golaw:hole` markers and their red tests; `golaw gen --check` must pass before you finish.

and one pointer sentence: queries go through the pinned sqlc and HTTP contracts through the pinned oapi-codegen, both run by `golaw gen`. Claude also receives the map at session start; Codex and Cursor receive it through this rule.

The escape: `// golaw:handwritten <reason>` in a file's leading comments marks a file under a kind path as written by hand on purpose, such as a port the engine cannot judge. The engine never generates for or into it, `golaw map` lists it with the reason, and `golaw scan` reports it as a note.

## Setup

`golaw setup --gen` builds sqlc v1.31.1, oapi-codegen v2.8.0 and golangci-lint 2.14.0 from the repository's tools module into the kit's tool directory, with a receipt each, so the post hook can run them; each generator is built only when the policy holds its capability (`db`, `api`, and `hexagonal` for goverter v1.11.1, which is pinned in the tools module and runs only in `golaw gen` and `make generate`). It is run by a person, optional and idempotent. A missing binary is a doctor line and a notice, never a denial: the hook skips that step, and `golaw gen` and the pipeline still run the generator through `go tool`. The generators are pinned in the enrolled repository's `tools/go.mod` and the kit never imports them. init writes that file without its sums, since init never reaches the network, so run `go -C tools mod tidy` once and commit `tools/go.mod` and `tools/go.sum` before the first contract: until then `golaw gen --check` answers `unmeasured` with exit 2 and names that command, never the `go mod download` hint of the go command, which at the repository root writes no `tools/go.sum`. `docs/setup.md` has the steps.

## Green by construction

Generated code passes the gate's four conditions on its first pipeline run with no hand fix:

1. Zero new violations: every file a kind writes, with its holes open, passes the lint asset, `golaw scan` at zero and the surface linters.
2. New code coverage at least 80: every regenerable line is covered by the generated tests of its own package, with no `-coverpkg`, each hole has a red test, and with the recorded fills of the golden slice the new code reaches 80.
3. New duplication at most 3 percent: regenerable parts stay thin, shared behavior is called from the support package, and fakes delegate to the recorder.
4. No unreviewed security hotspot: a hotspot is designed out, never marked safe and never excluded.

Files keep at most 300 lines and functions at most 40, cognitive complexity at most 15 and nesting at most 4, generated or not. The laws each golden slice asserts:

| Law | Gate condition | What the templates never emit |
| --- | --- | --- |
| S107-parameters | zero new violations, go:S107 | a function, literal or interface method with more than 7 parameters |
| S1192-literals | zero new violations, go:S1192 | a string literal of more than five characters three times in one non test file |
| no-regexp | no unreviewed hotspot, python:S5852 | a regular expression of any kind |
| no-http-literal | no unreviewed hotspot, typescript:S5332 | a literal holding a clear text `http://` URL |
| doc-ranges-only | no unreviewed hotspot, python:S1313 | an IP address outside the documentation ranges of RFC 5737 and RFC 3849 |
| no-suppression | zero new violations, `nolintlint` | a linter or gate suppression comment of any form |
| file-modes | no unreviewed hotspot, permissions | an `os` call with a mode wider than `0o600` for a file or `0o700` for a directory |
| no-credential-literal | no unreviewed hotspot, python:S2068 | a string literal assigned to a credential name; test secrets come from `crypto/rand` |
| context-from-test | zero new violations, `contextcheck` | a root context in a test instead of `t.Context()` |

The shapes the sessions had to rewrite by hand, and what the templates do instead:

| Rule or linter | Shape the sessions had to rewrite | What the templates do instead | Proof in the kit |
| --- | --- | --- | --- |
| go:S107, more than 7 parameters | a constructor with 8 parameters | a constructor takes the port values or one `Deps` or `Config` struct | revive `argument-limit` 7 in the lint asset; law S107-parameters |
| go:S3776, cognitive complexity over 15 in tests | integration tests at 17 and 18 | table driven tests, one helper per assertion step, no loop with branches in one body | gocognit 15 over test files in the golden lint run |

Each kind has a golden slice: a scratch module rendered from a fixture contract with two instances of the kind and the support package, committed at a base commit, generated, then filled with the recorded fill of each hole. With the kit's pinned tools and no Sonar call, the slice passes `go build`, `go vet` and `go test` in the pipeline's shape and the strict one; golangci-lint with the rendered asset at zero; `golaw scan .` and `golaw lint --surface` at zero, the latter under the strict set init writes into a new policy and skipped only when a surface tool is absent; `golaw coverage --new-code` against the base at least 80 with the fills and every regenerable line covered with the holes open; the duplication measure under 1.5 percent; `golaw gen --check` clean after the fills and failing on an open hole before them; byte identity with `golangci-lint fmt` and across the three operating systems; the laws above; and `go vet` of the filled slice with its go line lowered to the go 1.24 floor and the go1.24.0 toolchain, so a template calls only the standard library an adopter at the floor has (the step skips with its reason when the go command cannot reach that toolchain). The slices run in the kit's `make ci` as the `golden-gen` target.

The duplication proxy, `internal/dup`, tokenizes Go with `go/scanner`, drops comments, normalizes literals to their kind and keeps identifiers; a duplicated block is at least 100 tokens over at least 10 lines that occurs twice or more, and the density is duplicated new lines over new lines, test files included. Its threshold is 1.5 percent, half the gate.

## The gaps

- The coverage of the recorded fills proves the shape, not the agent's fills: a hole filled with branchy logic and one case can still miss the gate, which only the pipeline judges.
- The duplication proxy is uncalibrated against the remote copy detector, so its threshold is half the gate, and a cross file copy the proxy misses stays possible.
- Whether the pipeline analyses `zz_generated_*.go` beside owned code and `api/gen` as its globs imply was inferred, not measured on the server.
- A shell write to a generated path that is not literal is fed back, not denied, and the file stays edited until `golaw gen`; `golaw gen --check` in CI is the backstop.
- Codex and Cursor get the map through the skill rule only, which agents follow in part.
- A repository rich in generic or embedded ports gets the handwritten marker often, and the saving there is smaller.
- An area whose `Deps`, `UseCases` or `NewUseCases` were written by hand is out of reach of `golaw new usecase` in phase M7.1, and the refusal names a new area as the way out.
- The routes of a repository without `api/openapi.yaml` stay hand written, because the handler kind reads the OpenAPI contract.
- A field added across existing hand written layers (record, query, store, transport) has no kind in phase M7.1, so `golaw map` and the hook's sqlc run for a manifest query are all that help there.
- A repository whose `main` packages live under `cmd/` beside an empty root, or under `cmd/` twice, gets its bindings as `wire ... by hand` decision lines instead of a generated composition root.
- The golden slices build over recorded third party outputs whose exported shapes `internal/gentest/fidelity_test.go` holds to the pinned generators, and the fresh repository acceptance runs `make ci` over the real outputs.
